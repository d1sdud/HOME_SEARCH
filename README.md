## 집 찾기

**→ https://d1sdud.github.io/home-search/**

매물을 한 화면에 모아 놓고 지도로 보고, 조건을 넣으면 순서를 매겨 주는 도구.
엄마가 여러 앱을 오가며 메모하지 않아도 되게 만든 것이다.

- **`index.html`** — 사이트. 파일 하나로 끝나고, 더블클릭하면 브라우저에서 바로 열린다.
- **`collect.mjs`** — 매물 수집기. 출처를 골라 받아서 `data/listings.js` 를 만든다.
- **`lib/`** — 출처별 수집 코드. `zigbang.mjs` · `dabang.mjs` · `naver.mjs`.
- **`collect.config.json`** — 어떤 출처·지역·가격대를 받아 올지 적어 두는 곳.
- **`data/listings.js`** — 수집 결과. 수집기가 만드는 파일이라 직접 고치지 않는다.

수집과 사이트는 따로 논다. 어느 한 곳이 바뀌어 수집이 깨져도 **사이트는 마지막에 받아 둔
데이터로 그대로 돌아간다.** 한 출처가 실패해도 나머지 출처는 계속 받는다.

---

### 엄마가 쓰는 법

`index.html` 을 열면 끝이다. 설치도 로그인도 없다.

| 하고 싶은 것 | 하는 법 |
|---|---|
| 조건 걸기 | 왼쪽에서 거래 유형·예산·면적·지역·출처를 고른다 |
| 마음에 드는 집 담기 | 목록의 ☆ 를 누른다 |
| 담은 집 견주기 | 위쪽 **비교** 를 누르면 표로 나란히 보인다 |
| 본 집 기록하기 | 매물을 누르면 열리는 오른쪽 칸에 메모를 적는다 |
| 원문 보러 가기 | 목록의 **직방 ↗ / 다방 ↗ / 네이버 ↗** 를 누르면 그 매물 페이지로 바로 간다 |
| 관심 없는 집 치우기 | 매물 상세에서 **이 집 빼기** |

찜·메모·조건은 그 브라우저에 남는다. 기기를 옮기면 따라가지 않는다.

**기준 위치**를 지도에 찍어 두면(직장, 지금 사는 곳, 자식 집 같은 곳) 거리까지
따져서 순서를 매긴다. 이게 이 도구에서 제일 쓸모 있는 기능이다.

아파트 매물을 열면 **그 단지의 최근 실거래가**가 같이 나온다. 국토교통부에 신고된
실제 거래라서, 지금 부르는 값(호가)이 얼마나 벌어져 있는지 바로 보인다.

---

### 어디서 매물을 받아 오나

| 출처 | 받는 것 | 필요한 것 |
|---|---|---|
| **직방** | 아파트·빌라·오피스텔·원룸 + 아파트 단지 실거래가 | 없음 |
| **다방** | 아파트·오피스텔·빌라·원룸 | 없음 |
| **네이버** | 아파트·연립·다세대·빌라 | **구글 크롬 + `npm install playwright`**, 그리고 **집 컴퓨터에서 실행** |

네이버는 서버에서 바로 부르는 요청을 막고, 자동화 흔적이 보이는 브라우저도 돌려보낸다.
그래서 진짜 크롬을 띄워 그 안에서 부르는 길밖에 없고, **클라우드나 서버에서는 실패한다.**
맥북에서 돌리면 되고, 실패해도 직방·다방 수집은 그대로 이어진다.

네이버에서 오피스텔·원룸을 받지 않는 건 네이버가 그 유형에 쓰는 코드를 확인하지
못했기 때문이다. 아파트·빌라는 확인했다.

### 매물 새로 받기

```bash
cd home-search
node collect.mjs              # 설정한 출처 전부
node collect.mjs --only 직방,다방    # 네이버 빼고 (Node 만 있으면 된다)
```

Node 18 이상이면 직방·다방은 설치할 것 없이 돌아간다. 네이버까지 받으려면 한 번만:

```bash
npm install playwright        # 크롬은 이미 깔린 걸 쓴다. 따로 받지 않는다
```

받아 올 범위는 `collect.config.json` 에서 바꾼다.

```jsonc
{
  "sources": ["직방", "다방", "네이버"],   // 줄을 지우면 그 출처를 건너뛴다
  "regions": ["수원", "서울"],            // 여러 곳을 한 번에. 겹치는 범위는 알아서 한 번만 훑는다
  "kinds": ["아파트", "빌라", "오피스텔", "원룸"],
  "trades": {
    "전세": { "depositMax": 50000 },              // 만원 단위. 5억 이하
    "월세": { "depositMax": 20000, "rentMax": 150 },
    "매매": { "priceMax": 100000 }
  },
  "areaMinM2": 33,                  // 10평 이상만
  "geohashPrecision": 4,
  "maxItems": 20000,
  "realPriceCount": 6,              // 단지마다 최근 실거래 몇 건까지 담을지
  "dabang": { "maxPages": 60 },
  "naver": { "maxDongs": 400, "maxPages": 40, "pauseMs": 700 }
}
```

거래 유형을 통째로 빼려면 그 줄을 지우면 된다. 명령줄로 잠깐 덮어쓸 수도 있다.

```bash
node collect.mjs --region 수원            # 한 곳만
node collect.mjs --region 수원,성남,용인   # 여러 곳
node collect.mjs --skip 네이버             # 출처 하나 빼고
node collect.mjs --dry-run               # 몇 건 잡히는지만 세어 보기 (파일은 안 만든다)
node collect.mjs --bbox 37.49,127.02,37.53,127.07   # 남,서,북,동 좌표로 직접
```

쓸 수 있는 지역 이름: 서울 · 경기 · 인천 · 수도권 · 수원 · 성남 · 용인 · 화성 ·
부산 · 대구 · 대전 · 광주 · 울산 · 세종 · 제주.

### 추천 점수는 어떻게 나오나

사이드바의 **추천 기준**에서 항목별 중요도를 정하면, 매물마다 아래 다섯 가지를
0~100 으로 환산해 가중 평균한다.

| 항목 | 높아지는 조건 |
|---|---|
| 가격 | 같은 거래 유형 안에서 쌀수록 (월세·전세는 관리비 포함 월 실부담 기준) |
| 넓이 | 전용면적이 넓을수록 |
| 거리 | 지도에 찍은 기준 위치에 가까울수록 |
| 층 | 반지하·옥탑 0점, 1층 35점, 2층 72점, 3층 이상 100점 |
| 최신 | 최근에 올라온 매물일수록 (45일이 지나면 0점) |

**전세 보증금과 매매가를 한 줄에 놓고 비교하지는 않는다.** 순위는 같은 거래 유형
안에서만 매긴다. 매물 상세를 열면 그 집이 어느 항목에서 점수를 얻었는지 막대로 나온다.

### 알아 둘 것

- **같은 집이 여러 곳에 올라와 있다.** 거래 조건·면적·층이 같고 좌표가 붙어 있거나
  단지 이름이 같으면 한 건으로 묶고, 목록에 `직방·다방` 처럼 표시한다.
  여러 곳에 함께 올라와 있으면 실제로 나와 있는 매물일 가능성이 그만큼 높다.
  드물게 같은 건물의 서로 다른 호실이 묶일 수 있다.
- **다방은 좌표를 일부러 흐려 놓는다.** 지도 위치가 실제와 수십 미터 차이 날 수 있어서
  상세에 그렇게 적어 둔다. 직방·네이버는 실제 좌표다.
- **아파트는 관리비가 없다(직방).** 직방이 아파트 매물에 관리비를 싣지 않는다.
  그래서 '월 실부담'에도 그 아파트 관리비는 빠져 있다. 다방·네이버 매물은 들어 있다.
- **실거래가는 신고분이라 늦다.** 계약 후 신고까지 최대 30일이 걸리므로 가장 최근
  거래가 아직 안 보일 수 있다. 출처는 국토교통부, 직방이 중계하는 값을 받는다.
- **지역 경계는 네모다.** "서울"로 받아도 부천·고양·광명 같은 인접 지역이 딸려 온다.
  그래서 표기도 "서울 일대"다. 사이트의 지역 필터로 좁히면 된다.
- **월 실부담은 가정값이다.** 보증금을 월세로 바꿔 견주려고 전월세전환율을 곱한
  것이고, 기본값 4.5%는 사이드바에서 바꿀 수 있다. 실제 계약 조건이 아니다.
- **공식 API가 아니다.** 세 곳 모두 자기 웹사이트가 쓰는 통로를 그대로 쓴다.
  구조가 바뀌면 예고 없이 깨진다. 그때는 `lib/` 아래 해당 파일을 손봐야 한다.
  개인이 집 알아보는 용도를 넘어 자동으로 자주 긁지 않는 게 좋다.
